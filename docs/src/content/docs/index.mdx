## 1. Try it

This button subscribes your browser with the site's own VAPID key, then asks the Cloudflare Worker that serves these docs to send you one notification through this library. The Worker stores nothing.

<PushDemo>

```ts title="docs/worker/push-demo.ts" wrap hangingIndent=2
await sendPushNotification(subscription, NOTIFICATION, vapid, {
	ttl: 60,
	urgency: "high",
	timeoutMs: 10_000,
});
```

## 2. The four pieces

<Annotated>

<PieceList section={2}>

1. [`/vapid`](/reference/vapid/) <span>Generate your VAPID key pair once, on the server or in the browser.</span>
2. [`sw.js`](/getting-started/#2-add-a-service-worker) <span>A copy-paste service worker that shows the notification and handles the click.</span>
3. [`/client`](/reference/client/) <span>`subscribe()` resolves to subscribed, denied or unsupported.</span>
4. [`/send`](/reference/send/) <span>Send to one subscription, or fan out to a list. A gone subscription resolves `false`, so you know to delete it.</span>

</PieceList>

<MarginNote id="pieces">
	Each one tree-shakes on its own. The browser half is about 1.3 kB, the server
	half 3.6 kB, minified and gzipped.
</MarginNote>

</Annotated>

## 3. Runtimes

If it has `fetch` and `crypto.subtle`, it works. No Node emulation, no polyfills, no compat layer.

## 4. Security considerations

Payloads are encrypted with RFC 8291 `aes128gcm`, and every request is signed with RFC 8292 VAPID. The push service in the middle carries your message but can't read it.

<RelayDiagram>

<MarginNote id="relay" slot="note">
	Push services return 201 even when the payload is broken, so you'd never know.
	Hence the RFC's own test vector, pinned byte for byte.
</MarginNote>

</RelayDiagram>

<Annotated>

<mark>100% test coverage</mark>, and every release waits on conformance checks
in Node, Deno, Bun and Workers. Every push to the repository also delivers a
real notification through Chrome's and Firefox's push services.
